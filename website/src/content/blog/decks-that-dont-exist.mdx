Testing a deck on a deck is slow. A real deck has to be on the desk, its card flashed, its screen watched, its buttons pressed by hand. And testing it against CDJs needs CDJs. From 4 October, TriMixxx stopped needing either for most of its testing.

## A Raspberry Pi 4 on a Mac

`pi-qemu` runs a deck on an Apple-silicon Mac. It is QEMU's model of a Raspberry Pi 4, running on the Mac's own cores through Apple's hypervisor, and it boots the **deck's real SD card, unmodified**: its own kernel, device tree and initramfs. Where a Pi's firmware would read `config.txt` and apply its overlays, pi-qemu does that work on the Mac, using Raspberry Pi's own tools.

Getting there took **21 patches** to QEMU, each an exact edit that fails loudly if QEMU's code moves: DMA for the SD card, which took a boot from about 60 seconds to 22; a sound card that behaves like the deck's UCA222, line input included; saving every device's state, so a whole deck can be snapshotted; an SD card fast enough to boot in about five seconds; and the Pi's one-shot trial boot, so the update system could be tested before any card was flashed.

The snapshot is the trick. A freshly built card is booted until Mixxx has its sound card open, then saved, RAM and all. Every new emulated deck is a copy of that moment: **up in about three seconds, with Mixxx already running**.

## Everything a deck touches, faked faithfully

- **The controller.** A virtual S3 sits on the emulated Pi's UART. It is played from an on-screen panel or from the command line, and it compiles the real firmware's MIDI header in, so the contract between the controller and Mixxx can't drift between the real deck and the emulated one.
- **The screen.** Screenshots work headless, so a script, a person or a reviewer can see exactly what the deck shows.
- **USB sticks.** A folder on the Mac can be plugged into a deck as a FAT32 stick, built in memory and served file by file as the Pi reads it, without copying anything. A stick can be made as slow as a real one, and pi-qemu says what the deck read, file by file. This is how the gig's freeze was reproduced.
- **The network.** Several decks can share a virtual network, with pi-qemu forwarding frames between them like a switch. Each deck claims its own Pro DJ Link player number; they browse each other's sticks and play each other's tracks.

It isn't a perfect copy, and doesn't pretend to be: the graphics are drawn in software, the cores are the Mac's, and the RAM is half a real deck's. It tests behaviour, not the GPU or timing.

## A CDJ-2000NXS, on its own firmware

Decks talking to decks is half of Pro DJ Link. The other half is CDJs, and those weren't on the desk either. On 10 October they joined the emulated network through [cdj2000-emulator](https://github.com/cdj2k-revival/cdj2000-emulator), an emulator of the CDJ-2000 that boots the player's own firmware: its main processor on a QEMU machine built for it, its interface processor in a simulator, its DSP interpreted.

<Photo id="2026-10-15-emulated-cdj" />

The firmware is Pioneer's, supplied by the player's owner, and is never in any TriMixxx repository. What TriMixxx added is the plumbing to put an emulated NXS on a deck's network, and fixes to the emulator itself, offered back upstream:

- frames shorter than 60 bytes are now padded, because the deck's 42-byte ARP replies were being dropped as runts and the CDJ never learned the deck's address;
- a way to put an emulated NXS on a Pro DJ Link network next to decks;
- and three fixes to time on macOS, which together took the emulator from 0.64–0.74 of real time to real time: keep-alives every 2.000 seconds, against a real player's 2.003.

The first two were merged upstream on 12 October; the timing fixes are on offer.

## What it changed

With a booth on a laptop, a protocol change could be tested the same way every time, on a network that never misses a packet, before anyone carried hardware anywhere. Master hand-overs the hardware session had never tried were captured between two emulated NXS players; the way CDJs serve sticks with no rekordbox library on them, for which there was no hardware capture at all, was worked out on them; and a deck between two emulated CDJs became the test a Pro DJ Link change had to pass before merging.
